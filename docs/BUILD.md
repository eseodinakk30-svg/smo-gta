# Как получить APK

Собирать локально ничего не нужно — всё делает GitHub Actions.
Нужны только два секрета: почта и пароль аккаунта Unity.
Готовый файл кладётся в **Releases** и скачивается одним тапом с телефона.

---

## Шаг 0. Workflow должны быть в ветке по умолчанию

GitHub показывает кнопку **Run workflow** только для тех workflow, файл которых
лежит в **ветке по умолчанию** репозитория (обычно `main`). Само по себе это
ограничение интерфейса: через API запуск с любой ветки работает и без слияния,
но кнопки в приложении GitHub не будет.

Поэтому сначала одно из двух:

* влей рабочую ветку в `main` (Pull request → Merge), **или**
* сделай рабочую ветку веткой по умолчанию:
  `Settings → General → Default branch → Switch to another branch`.

После этого в `Actions` появятся три пункта: «0. Проверка кода», «1. Быстрая
проверка проекта», «2. Сборка APK».

---

## Шаг 1. Добавить два секрета (один раз)

Нужен бесплатный аккаунт Unity — регистрация на https://id.unity.com

В репозитории открой:

`Settings → Secrets and variables → Actions → New repository secret`

Добавь два секрета:

| Имя | Значение |
| --- | --- |
| `UNITY_EMAIL` | почта аккаунта Unity |
| `UNITY_PASSWORD` | пароль этого аккаунта |

Три вещи, на которых спотыкаются чаще всего:

* Пароль нужен именно от **Unity ID**. Если входишь в Unity через Google, Apple
  или Facebook, отдельного пароля у аккаунта нет — задай его на
  https://id.unity.com в разделе Security.
* **Двухфакторная аутентификация** ломает активацию в CI. Её нужно временно
  отключить в настройках Unity ID.
* При копировании легко прихватить пробел или перевод строки — в секрете лишних
  символов быть не должно.

Файл лицензии (`.alf` / `.ulf`) не нужен: Unity закрыла ручную активацию
Personal-лицензий, и сборка активируется напрямую по логину и паролю.

---

## Шаг 2. Проверка кода — 30 секунд, без секретов

`Actions → «0. Проверка кода (без Unity)» → Run workflow`

Компилирует все игровые скрипты обычным C#-компилятором против stub-сборки
Unity API. Ловит опечатки и битые ссылки между системами за полминуты, не
тратя ни минуты Unity и не требуя лицензии. Запускается сам на каждый push.

## Шаг 3. Быстрая проверка проекта — ~15 минут

`Actions → «1. Быстрая проверка проекта» → Run workflow`

Скачивает Unity, активирует лицензию, компилирует проект настоящим Unity и
прогоняет автонастройку проекта. APK не собирает, поэтому идёт заметно быстрее
полной сборки: если сломана лицензия или настройка — узнаешь через пятнадцать
минут, а не через полтора часа.

Зелёная галочка — можно собирать APK.

## Шаг 4. Сборка APK

`Actions → «2. Сборка APK» → Run workflow`

Три параметра:

* **architectures** — `arm64` (только 64-битные телефоны, собирается вдвое
  быстрее) или `both` (ARMv7 + ARM64, встанет на что угодно).
  Любой телефон после 2016 года — ARM64.
* **format** — `apk` для установки на телефон, `aab` для Google Play.
* **release** — публиковать ли файл в Releases. Оставь включённым.

Первая сборка дольше: Unity качается и кэшируется. Последующие идут быстрее.

## Шаг 5. Установка

Готовый файл появится в двух местах:

* **Releases** — отдельным файлом, скачивается одним тапом с телефона;
* внизу страницы запуска, в разделе `Artifacts` — там zip.

Скачай `.apk`, открой, разреши установку из неизвестного источника. APK подписан
отладочным ключом Unity — для своего телефона этого достаточно.

## Сборка на компьютере

Если Unity всё же есть:

1. Unity Hub → *Installs* → Unity **2022.3.62f1** с модулем
   **Android Build Support** (вместе с Android SDK & NDK Tools и OpenJDK).
2. Unity Hub → *Add* → выбери корень репозитория. Первый импорт подтянет URP 14
   и запустит автонастройку (`Assets/Scripts/Editor/ProjectAutoSetup.cs`).
   Если не отработала — меню **San Monica → Setup Project**.
3. Меню **San Monica → Build → Android APK** → `Builds/SanMonica.apk`.

Из командной строки:

```bash
Unity -batchmode -quit -nographics \
      -projectPath . \
      -executeMethod SanMonica.EditorTools.BuildScript.BuildApk \
      -logFile -
```

Поиграть без сборки: открой `Assets/Scenes/Boot.unity` и нажми **Play**.

### Подпись для Google Play

1. `Edit → Project Settings → Player → Publishing Settings → Keystore Manager`
   → создай keystore и alias.
2. Собери **AAB**: меню **San Monica → Build → Android App Bundle (AAB)**
   или `-executeMethod SanMonica.EditorTools.BuildScript.BuildAab`.
3. Можно передать keystore аргументами:
   `-keystore /path/key.keystore -keystorePass … -keyalias … -keyaliasPass …`

## Если сборка упала

Открой упавший запуск в `Actions`, разверни красный шаг — там текст ошибки.
Внизу страницы запуска лежат артефакты `unity-logs-*` с полным логом Unity.

| Сообщение | Что делать |
| --- | --- |
| `Нет секрета UNITY_EMAIL` | не добавлен секрет, см. шаг 1 |
| `Invalid Credential` / `code 143.002` | Unity ID отверг логин или пароль: опечатка, лишний пробел в секрете, вход через Google/Apple без своего пароля, либо включена двухфакторка |
| `error CS____` | ошибка компиляции C#, номер строки — в тексте ошибки. Прогони сначала «0. Проверка кода» — она находит это за 30 секунд |
| `No space left on device` | собери с `architectures: arm64` |
| Кнопки `Run workflow` нет | workflow не в ветке по умолчанию, см. шаг 0 |
| `ENOENT ... open 'ProjectSettings/ProjectSettings.asset'` | этот файл обязан лежать в репозитории: после установки модулей `unity-setup` читает из него настройки Android. Файл закоммичен, так что появиться такое может только если его удалили |
| `[Android SDK Build Tools] failed to install` | сам по себе не причина: на втором проходе Hub пишет `already installed`, и сборка идёт дальше. Настоящую ошибку ищи ниже по логу |

Ищи ошибку по **всему** логу, а не по последним строкам: шаг очистки в конце
часто печатает свои собственные жалобы, которые к настоящей причине отношения
не имеют. И не верь первой красной строке: установщик Unity Hub рапортует о
сбое модуля, который на следующем проходе спокойно ставится, — настоящая
причина бывает на сотню строк ниже.
